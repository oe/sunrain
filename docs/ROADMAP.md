# Sunrain 产品实施路线图

> 制定日期：2026-09-03

## 产品判断

Sunrain 不应扩张为泛心理健康门户，也不应在缺少临床治理和效果证据时提供 AI 治疗建议。当前定位收敛为：无需注册、心理健康回答只留在设备上、在情绪困难的当下提供可信的短程自助。

## 阶段 0：安全与信任基线（立即）

目标：在扩大访问前消除高风险误导，并使隐私承诺与实际基础设施一致。

- PHQ-9 第 9 题任何非零回答均独立触发安全提示，不受总分等级影响。
- 在答题当下和结果页同时提供本地化危机支持入口。
- 明确说明测评答案和分数只保存在设备上，同时披露托管/CDN 可能处理匿名访问与性能数据。
- 为上述规则增加自动验证。

验收：8 种语言键完整；PHQ-9 安全触发可自动验证；生产构建通过；专业人士复核提示文案和热线数据。

## 阶段 1：建立可信流量基线（2 周）

目标：把 Cloudflare 独立 IP 与真实页面访问区分开。

- Cloudflare Web Analytics 已启用；以 2026-09-04 之后连续 14 天作为首个稳定观察窗口。
- 仅采集页面浏览、来源、国家/地区和 Core Web Vitals；不采集答案、分数、搜索内容或本地历史。
- 连续观察至少 14 天，记录入口页、热门路径、来源、设备和性能。
- 建立每周固定看板：真实访问、搜索流量占比、核心页面访问占比、错误率和 Core Web Vitals。
- 基线期不停止产品工作；“焦虑当下”切片可以并行设计和审阅，但在观察窗口结束前不进入首页主导航。

验收：能区分 HTTP 请求、机器人流量和真实页面访问；隐私文案与实际采集保持一致。

## 阶段 2：最小产品漏斗（1 至 2 周）

目标：知道用户是否真正完成核心任务，而不仅是打开页面。

- 先只发布“我现在很焦虑”一个意图入口，不同时扩张睡眠、量表和安全入口。
- 将入口、两分钟稳定动作和下一步建议拆成独立页面路径，使用现有 Cloudflare Web Analytics 观察路径访问量。
- 页面访问比只作为方向性信号，不把无会话标识的页面计数包装成精确用户转化率。
- 暂不建设自定义事件、数据库或用户级分析；只有页面统计无法回答明确产品问题时，再评估 Cloudflare Analytics Engine 或成熟分析产品。

验收：三个路径均可独立访问并被 Cloudflare Web Analytics 识别；全流程不上传心理健康回答、分数或自由文本；安全出口始终可达。

## 阶段 3：从工具集合变成连续自助（2 至 4 周）

目标：提供一次测评之后仍有价值的结构化路径。

- 设计 5 节压力管理计划：觉察与落地、与想法脱钩、容纳情绪、价值行动、自我关怀。
- 每节 5 至 10 分钟，进度只保存在本地，可离线继续。
- 测评结果只推荐一个最合适的下一步，不把分数包装成诊断。
- 使用 WHO 等循证材料前完成许可核对、来源标注和专业审阅。

验收：用户可在不注册的情况下完成并恢复课程；安全出口在每节内容中始终可达。

## 阶段 4：内容与自然增长（持续）

目标：先提高内容深度，再扩语言和页面数量。

- 优先英文和简体中文，建立焦虑当下、睡眠、量表解释、何时求助四个内容簇。
- 每篇内容标注资料来源、审阅者和更新时间。
- 接入 Google Search Console 和 Bing Webmaster Tools，按真实搜索词决定下一批内容。
- 只有核心页面在某语言获得稳定访问和复用后，才继续扩展该语言内容。

验收：自然搜索访问、核心工具进入率和回访呈持续改善；不以 sitemap URL 数量作为增长指标。

## 阶段 5：可持续模式（有留存后）

保持核心功能免费且无广告。优先尝试捐赠、公益赞助，以及面向学校和 NGO 的白标部署、本地化和内容维护服务；不以测评结果做广告定向或销售线索。
